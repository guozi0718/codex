# 【产品 / 模块名称】产品需求文档

> 产品版本：【V1.0.0】
> 文档版本：【V1.0.0_YYMMDD】

> 适用范围：【端 / 角色 / 模块】
> 文档原则：只描述本次交付的最终需求。各页面的字段及其逻辑集中写在对应页面章节；一个字段占表格一行，行内可用 `<br>` 换行。每条提示文案、校验条件、触发时点、反馈方式和失败后状态写在**触发它的字段、按钮或对应页面的同一章节**；不得另设“提示文案汇总”“校验规则汇总”章节替代字段描述。未确认的规则标记为【待确认：问题】，不得推测或写成已确定规则。原型中已删除的功能不写入正文，也不把第一版写成优化或迭代。

## 文档说明

### 名词解释

| 术语 / 缩略词 | 说明 |
|---|---|
| 【业务日期】 | 【定义、权威数据来源、时区、与客户端时间的关系；若不适用则删除本行。】 |
| 【统计对象】 | 【计数或计分的最小单位；一次操作与一条记录是否一一对应。】 |
| 【有效记录】 | 【何时生成、何时参与统计、删除后是否仍用于审计。】 |
| 【历史快照】 | 【哪些字段在什么时点固化；配置、组织、人员变化后如何展示。】 |
| 【其他术语】 | 【消除研发、测试、设计对同一词的不同理解。】 |

> 编写约束：所有数值字段都在其所属页面或规则表的**同一字段行**写明最小值、最大值、边界是否包含、精度、格式、默认值、步长、清空和超限处理；还须分别写明接近极值时的最后一步、达到极值时的数值与按钮外观、极值状态下再次点击的准确提示。筛选、日期、附件、权限和空状态的提示与校验也放在所属字段、按钮、页面或弹窗行，不能在末尾另列一份让研发跨章节查找；跨字段提交失败才写在本页面“页面级提交与跨字段异常”中，且需指明受影响字段。仅在名词解释中定义术语，不能用“详见通用规则”代替页面字段逻辑。金额、分值、次数、人数、字数、图片数量、文件大小、日期跨度、列表容量均适用。若限制来自配置，写清配置来源、当前取值、读取及生效时点、变化后的处理；取值未确认则标【待确认】，不得自行给数。

> 待定内容标注：用户明确说“暂定”的规则使用黄色底色，例如 <mark>【暂定：规则及待确认点】</mark>；用户表示稍后自行描述的内容使用红色标注，例如 <span style="background-color:#ffe3e3;color:#b42318">【待用户补充：具体字段或问题】</span>。仅用这两类标注对应其原意；尚未得到回答的普通问题使用【待确认：具体问题】，不可混写为已确定规则。若阅读平台不支持 HTML 颜色，仍保留方括号内的“暂定 / 待用户补充 / 待确认”文字以免丢失语义。正式定稿后只保留仍未确定的标注，不能把暂定写成已确定。

> 填写要求：每个看板指标都要在其**同一字段行**分别写出无数据、部分数据、全量数据的展示值及计算规则，再用状态行说明整个区域的文案、卡片、按钮和可执行操作；三种状态均需给出实际示例。无数据指查询成功且有效数据为零，部分数据须区分“业务上只有部分字段有值”和“尚未加载完”，全量数据须明确查询范围与完整性。若接口提供已汇总值，不得仅按已加载的部分卡片推算全量看板；若支持实时变更，写明刷新触发和一致性口径。
