# 控辍保学与关爱个案联动（第二版方案）

## 1. 目标与边界

在老师端控辍保学菜单的预警记录中，复用第一版“关爱个案—多次关爱”数据与表单，增加“关爱／继续跟进”入口。预警详情同时只读展示该预警的劝返记录和关联个案的多次关爱记录。劝返与关爱是两类独立业务记录，不能相互覆盖、合并计数或以劝返自动代替关爱。

第二版不重做学校端和四级监管端的关爱菜单，不改变第一版创建日期、个案状态、关联信息、人员权限和校验规则。生产实现以预警 ID、学生 ID、学校 ID、学年及个案 ID 关联；原型的姓名与班级只用于演示匹配，不可作为正式关联键。

## 2. 入口与状态

| 位置 | 条件 | 展示／动作 |
| --- | --- | --- |
| 控辍保学预警卡 | 尚无关联关爱个案 | “关爱”，打开第一版新增关爱个案页，预填当前学生、预警来源与当前预警关联信息；允许仅建案不填首次关爱。 |
| 控辍保学预警卡 | 已有关联个案且无关爱记录 | “关爱”，进入该个案首次关爱表单，不重复建案。 |
| 控辍保学预警卡 | 已有关联个案、至少一条关爱、状态关爱中 | “继续跟进”，进入该个案新增关爱记录表单，保存后返回新版个案详情。 |
| 控辍保学预警卡 | 关联个案已完结 | “查看关爱”，进入只读详情；不允许继续跟进。 |
| 预警详情 | 任意 | 展示预警信息、劝返信息（共 N 次）、关爱情况（共 N 次）和同状态入口；零记录有明确空态。 |

按钮在删除最新关爱记录、提交关爱或完结个案后实时重新计算。处理／重新处理属于劝返流程，保留独立入口，不影响关爱状态。预警列表或详情点击“关爱”不得跳回旧版 `sc-care-add` 表单。

## 3. 预警详情展示

预警基本信息包含姓名、学校、年级、班级、预警类型、原因、日期与处理状态。劝返区逐条展示劝返日期、方式、老师、结果与已有佐证材料；关爱区按第一版个案顺序展示每一次关爱时间、执行人员、方式、结果、证明材料数量、继续跟进及可选下次跟进日期。两区各自计数、各自空态，长内容完整换行。当前演示数据的本学年预警与劝返日期统一在 2026 年 9 月，上一学年历史记录保留历史学年标识；生产日期来自事件实际时间，不能为对齐演示而改写真实记录。

## 4. 数据和一致性

- 个案、关爱记录复用第一版实体与权限。预警与个案需保存显式关联键；同一预警多次劝返、多次关爱分别维护一对多关系。
- 新增关爱个案时，控辍预警作为关爱来源之一；关联信息可选、可多选，不作为提交必填条件。关联信息文案完整展示缺勤工作日及具体日期。
- 从预警进入新增关爱时，预填学生与当前预警；变更学生后须重新核验关联项。已有未完结个案的重复建案限制沿用第一版。
- 个案删除、关爱记录删除和状态变化后，预警卡及详情需即时刷新计数、按钮和记录；劝返历史不随个案删除而丢失。
- 用户身份、班主任范围、记录编辑与删除规则完全沿用第一版；当前老师只读查看他人关爱历史，不能凭预警入口获得额外编辑权。

## 5. 验收示例

1. 本学年预警无个案：预警卡显示“关爱”，点击预填学生与预警；仅建案后预警详情显示 0 次关爱，个案待关爱。
2. 同预警关联个案有两次关爱：预警详情逐条展示两次，卡片显示“继续跟进”；新增第三次后立即显示三次。
3. 已完结个案：预警卡“查看关爱”进入只读详情，不可新增跟进。
4. 新增或重做劝返：只改变劝返区，不新增关爱记录；预警与劝返示例时间均为 2026 年 9 月。
5. 删除最新关爱：列表和预警详情计数同步减少；若变为零次，入口回到“关爱”。

## 6. 待确认

同一学生同学年有多条预警时，预警详情中的关爱记录是仅显示显式关联当前预警的个案，还是显示该学生本学年全部控辍来源关爱个案。正式关联键和多预警验收用例据此确定。
