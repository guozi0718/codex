## 需求背景

原有“新增关爱即生成一次记录”的流程不能表示尚未实施首次关爱的学生，也将个案原因、线索与每次关爱内容混为一层。本版改为先建立学生个案，再按时间追加零至多次关爱记录；一个学生在同一学校不能同时存在两个未完结个案。老师通过个案了解成因，通过每次记录呈现实际关爱与跟进结果。

## 文档说明

### 名词解释

| 术语 | 定义与统计口径 |
|---|---|
| 关爱个案 | 同校同生某一段连续关爱过程的容器。创建后即存在，允许零条关爱记录。完结后新发生的关爱原则上新建个案，不并入旧案。 |
| 关爱记录 | 一次成功提交的实际关爱内容。多次记录同属一个个案，详情按关爱时间倒序、同日按提交时间倒序。 |
| 关爱类型 | 个案层的需要帮助的问题类别，可选一项或多项，不等于实施手段。 |
| 关爱来源 | 个案层的线索渠道，可选一项或多项，不等于关爱原因。预警／测评来源可关联本学年多条原始记录。 |
| 关爱原因 | 对该学生本次个案的具体情况写一段事实描述，所有来源共用一段，不逐来源分别填写；最多100字。 |
| 关爱方式 | 单次关爱记录层的实际实施方式，本期单选。 |
| 当前学年 | 取已有系统配置，前台所有学生、预警／测评关联信息、个案统计与编辑范围以此判断。 |
| 版本快照 | 创建或修改成功后追加不可覆盖的版本，包含修改前后内容、填写账号ID、当时角色、服务端时间。详情只展示当前版本，历史由审计能力查询。 |

## 需求范围

| 功能点 | 本期范围 | 明确边界 |
|---|---|---|
| 关爱个案列表 | 全部／待关爱／关爱中／已完结、按姓名检索、当前学年个案数 | 数量按个案而非关爱记录统计。 |
| 新增关爱个案 | 级联选择学生；类型与来源多选；原因文本；可选同时填写零至多条关爱内容 | 不允许同校同生存在另一未完结个案。 |
| 个案详情 | 个案信息与全部关爱记录、时间倒序、状态和底部动作 | 已完结个案底部继续跟进置灰；可依权限编辑最新记录将状态改回关爱中。 |

## 功能详细说明

### 业务范围与数据口径

| 规则 | 处理方式 | 异常／边界 |
|---|---|---|
| 学生范围 | 年级→班级→学生姓名三级联动，仅本学年有效年级、班级及在读学生。 | 上游学生状态变更时，提交阻断并提示“学生状态变更，请重新进入页面”。 |
| 个案唯一性 | 同一学校、同一学生同时最多一个“待关爱”或“关爱中”个案；“已完结”可保留多件。 | 新建提交须服务端原子检查；冲突提示“该学生已有未完结的关爱个案，请进入原个案继续关爱”。 |
| 个案创建日期 | 创建个案成功时由服务端固化；即使尚无关爱记录也有创建日期。 | 后续修改关爱时间不反写创建日期。 |
| 关爱次数 | 当前个案未删除的关爱记录数量；可为0。 | 新增+1、删除最新-1、编辑不变。 |
| 状态 | 记录数=0→待关爱；≥1且最新记录选“需要”→关爱中；≥1且最新记录选“不需要”→已完结。 | 删除最新一条后，依据新的最新记录重算；删除唯一记录回待关爱。 |
| 日期 | 业务日期统一显示YYYY-MM-DD；填写／编辑／审计时间由服务端时间确定。 | 关爱时间仅可选今天及之前；下次跟进日期可选今天及以后。学年边界沿用已有系统，原型日期仅示例。 |
| 删除 | 前台移除并重新计算个案数／状态；正式实现保留审计与删除操作人。 | 删除确认前复核权限和最新记录状态；不可据旧页面状态直接写入。 |

### 页面一：关爱个案列表

#### 页面目标

从已有菜单入口查看当前学年的学生个案，识别“待关爱、关爱中、已完结”，进入对应个案或新建个案。只改关爱菜单，不改其他菜单。

#### 页面字段与交互

| 区域 | 展示／动作 | 规则 |
|---|---|---|
| 页头 | 关爱个案、返回、已有提示文案入口 | 返回进入前一菜单；提示文案按当前页面显示。 |
| 分类 | 全部、待关爱、关爱中、已完结 | 按个案状态筛选；无记录个案归待关爱。 |
| 检索 | 搜索学生姓名 | 在当前学年与当前权限范围内筛选。 |
| 统计 | “本学年共 N 个关爱个案” | N 为当前状态标签及学生姓名搜索条件下、本学年实际展示的个案数；切换标签、搜索或删除后即时重算。 |
| 个案卡 | 学生姓名、年级班级、状态、创建日期、关爱类型、关爱来源、关爱原因、关爱次数；有记录时另列最近关爱及最新关爱结果 | 结果最多三行省略，进入详情看全文；卡片点击进入详情。 |
| 卡片动作 | 三种状态均仅显示“删除个案” | 点击卡片进入详情；关爱／继续跟进统一在详情底部进入。删除依当前角色／班主任身份与创建、参与权限校验。 |
| 底部 | 新增关爱个案 | 进入空白新增关爱个案表单；普通关爱菜单旧入口指向同一新版页面。控辍保学联动入口按第二版《控辍保学-关爱联动-PRD》执行。 |

展示规范：个案卡、详情和编辑表单沿用控辍保学卡片的无字段横线样式，各字段保持一致的上下留白，长文本自然换行；字段名、辅助提示小于正文，正文和操作按钮字号保持一致。操作按钮沿用原型的浅色描边次要按钮与蓝底白字主要按钮样式。仅保留上传规格、空态、校验错误等有提示作用的文字，不展示内部锁定或版本快照规则的解释性段落；这些规则仍须按下文执行。

### 页面二：新增／编辑个案

#### 页面目标

先记录“谁需要关爱、因何需要关爱”，允许只建空个案，也允许在一次提交中填写多次关爱。每张关爱卡均可单独取消，不影响个案信息或其他关爱卡。

#### 字段顺序及校验

| 顺序 | 字段 | 控件与规则 | 来源／默认值 |
|---|---|---|---|
| 1 | 年级* | 单选、必填，变更清空班级和学生 | 当前学校本学年有效年级。 |
| 2 | 班级* | 单选、必填，变更清空学生 | 所选年级有效班级。 |
| 3 | 学生姓名* | 单选、必填；无在读学生给空状态 | 所选班级本学年在读学生。 |
| 4 | 关爱类型* | 与字段名同行显示已选项；点击打开底部弹窗，可单选或多选，确定后回显；至少1项；选“其他”无需补充填写 | 家庭变故、学业困难、同伴关系、行为问题、经济困难、特殊家庭、其他。 |
| 5 | 关爱来源* | 与字段名同行显示已选项；点击打开底部弹窗，可单选或多选，确定后回显；至少1项；占位文字不可成为选项 | 辍学预警、心理测评、班主任发现、任课教师反映、学生主动反映、家长反映、困难学生、欺凌事件、其他。 |
| 6 | 关联信息 | 选择辍学预警时固定显示“关联控辍保学”，选择心理测评时固定显示“关联心理测评”；字段名与选择区同行。点击进入底部弹窗，选项区一次可显示五条、超出上下滚动；每类可单选或多选，确定后回显“已选N条关联信息” | 两字段均非必填，不选择也可提交。仅加载该学生本学年对应记录；无数据提示“本学年暂无该学生对应数据信息”。新增与编辑一致。控辍保学展示“连续缺勤N个工作日（起止日期）”或“10个工作日内缺勤N个工作日（逐一列明缺勤日期）”；心理测评展示“（本学期）无需关注／一般关注／重点关注／紧急关注”，同级多条记录须可辨认。 |
| 7 | 关爱原因* | 文本输入、必填、最多100字；多项来源仍只填一段 | 说明需要关爱的实际情况；“其他来源”的具体情况写在此处。 |
| 8 | 新建关爱 | 按钮上方展示与“个案信息”同级样式的“关爱情况”标题；按钮非必选，居中放置、蓝底白字、无加号；每次点击追加一张独立关爱卡；每张卡可单独取消、重新编号 | 不添加关爱卡时仅保存个案并进入待关爱；添加多张时按显示顺序逐条保存，前一条必须选择“需要”继续跟进，关爱日期不得逆序。 |

保存前核验必填字段完整、学生状态、已选择的关联源记录仍有效及当前学校是否已有未完结个案；未选择关联信息本身不构成校验失败。已选来源记录变化时提示“预警记录状态变更，请重新进入页面”或对应测评提示。重复点击需幂等，不得生成两案或两条首记。

当前执行口径为“多项关爱来源对应一段关爱原因”，同时逐来源保存预警／测评关联记录ID和快照。产品建议继续采用这一口径：一段原因适合描述同一学生的总体情况，避免老师重复填写；若未来需要区分不同来源的独立事实，可新增“线索明细”，不把原因字段拆成多段。本期不增设该能力，是否在后续版本引入仍待产品确认。

#### 个案编辑边界

无关爱记录时仅创建人可编辑个案类型、来源、关联信息、原因；学生身份不变。产生首条关爱记录后，整个个案信息不可编辑，点击“编辑个案”提示“已有的关爱内容，个案信息不可编辑”。此前发生的个案信息变更仍逐版追加快照；个案详情显示最新值。角色变更后不得以历史权限修改。未授权操作提示“暂无权限”。

### 页面三：新增关爱／继续跟进／编辑关爱

| 顺序 | 字段 | 规则 |
|---|---|---|
| 1 | 关爱时间* | 默认今天，YYYY-MM-DD，必填；选择器可切换上／下月，今天之后不可选。 |
| 2 | 执行人员* | 默认勾选所选学生当前全部班主任；有多个班主任时均选中、逐人回显。可在底部弹窗多选调整，必填；正式数据来自已有教师角色／人员数据，不采用原型示例名单。 |
| 3 | 关爱方式* | 单选：谈心谈话、家校沟通、家访、学习辅导、生活关怀、同伴关系协调、行为教育、资助帮扶、返校关怀、其他。 |
| 4 | 关爱结果* | 记录实际过程与结果，必填，完整换行展示。 |
| 5 | 证明材料 | 可不上传；仅JPEG/JPG/PNG，最多九张，每张不超过10M；上传按钮位于缩略图网格首位、大小与缩略图一致，上传第九张后立即隐藏；缩略图可移除和查看原图。 |
| 6 | 继续跟进* | 单选“需要／不需要”；未选择不可提交。 |
| 7 | 下次跟进日期* | 仅继续跟进=需要时显示并必填；未填写时占位文字为“请选择日期”；选择“不需要”时隐藏并清空。点击打开底部日历，可切换上／下月，选今天及以后日期并按YYYY-MM-DD回显。 |

“新建关爱”可随创建个案一次提交零至多条记录；每张卡的取消按钮统一为描边样式，证明材料独立保存和校验。后续“关爱／继续跟进”针对已有个案添加新记录。关爱时间点击打开底部日历，可切换上／下月，仅今天及之前可选，按YYYY-MM-DD回显；不能直接输入未来日期。小程序选择控件均以底部弹窗选择并在原字段同行回显，选项区最多露出五条并可上下滚动；箭头统一为细线、垂直居中。日期采用底部日历。滚动时隐藏滚动条但保留手势滚动。操作页标题区展示对应提示小红点按钮，记录详情页不展示。记录保存后进入该个案详情；来源、类型、原因只从个案读取，不在单次关爱表单中重复编辑。新增和编辑页面返回原来进入的页面，不应回到无关菜单。

### 页面四：关爱个案详情

个案信息置顶：学生、创建日期、状态、关爱类型、关爱来源、关联信息、关爱原因。关联信息无记录显示“--”，有记录显示“关联N条信息”；点击打开底部弹窗，标题带总数，按关联类别分组、组内按勾选顺序逐条完整换行展示，内容区可上下滚动，底部有关闭按钮。其下“关爱情况（共N次）”按最新至最早逐卡展示；每卡严格按“关爱时间→执行人员→关爱方式→关爱结果→证明材料→继续跟进→条件性下次跟进日期”排列。中间内容滚动，底部按钮随记录实时变化：0次为“关爱”，≥1次且关爱中为“继续跟进”，已完结时“继续跟进”置灰；删除最新记录后立即重算。证明材料点击原图，关闭入口靠近原图。普通详情只展示每条最新有效版本，不展示审计快照。

### 权限、版本与删除

| 场景 | 允许／拒绝 | 留痕要求 |
|---|---|---|
| 新增首次关爱或后续跟进 | 当前班主任身份可接手本班学生的个案；不得因此修改前任班主任历史记录。 | 每条记录保存填写账号ID、角色、服务端填写时间及首版快照。 |

## 通用权限、数据与异常规则

1. 服务端以账号ID、当前角色及学年配置校验可见、可新增、可编辑、可删除；前端按钮状态不是权限依据。
2. 新增个案、增加关爱、编辑、删除均采用提交时二次校验与幂等控制；涉及“同校同生唯一未完结个案”的操作应使用事务保护。
3. 预警和测评关联保存原始记录ID、关联时展示快照及原记录状态。原记录后来变化不静默改写既有个案，编辑或再次提交时按业务校验阻断。
4. 审计版本区分个案层与关爱记录层；包含创建、编辑、删除，至少留人、角色、服务端时间、修改前后数据。普通用户只看最新有效版本。
5. 图片按上传规则验证内容类型与大小；正式环境需满足未成年人敏感信息的鉴权、访问控制和留存要求。

## 验收要点

1. 可仅建个案，列表显示“待关爱”、次数0；也可一次新增多张关爱卡并保存为多条独立记录，前一条需选择“需要”且日期按顺序填写；个案状态依最后一条的“继续跟进”变“关爱中／已完结”。
2. 类型和来源都可多选，枚举和字段顺序正确；选“其他类型”不出现补充输入；原因只有一段，≤100字。
3. 同时选预警和测评时分别显示“关联控辍保学”“关联心理测评”，可选各自本学年信息，也可两项都不选并成功建案；原因仍只填一段。已选但失效的关联和并发重复建案被服务端阻断。各小程序下拉从底部弹出，选项区可见五条、超出滚动并正确回显。
4. 一个个案多条关爱记录倒序展示；删除最新一条后次数、最近关爱、状态实时按剩余最新记录计算。
5. 更早记录仅结果、图片可编辑，且不可删除；本人权限与现任班主任接手规则不相互混淆。
6. 图片九张后上传入口隐藏；格式、体积、日期、必填与页面级提示准确。
7. 各次提交和修改可通过审计查到逐版快照、账号ID、角色、时间；前台详情只显最新版本。
8. 家长端在本期所有入口和交付范围中隐藏。
