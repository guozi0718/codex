# 学生关爱第一期：方案总览与验收口径

> 第一期确认补充（2026-10-10）：学校与四级监管台账的关爱来源、关爱类型列居中，按字符计数超过10字展示前10字加“...”，悬停显示完整文字。第二版老师及Web关爱情况在已建案后显示唯一顶部个案信息卡（创建日期→来源→关联信息→类型→原因）；未建案不显示，已建案零次也显示，增加内容不重复生成，不改变原内容顺序。家长端原型、专属文档、测试与入口删除，不保留旧副本或兼容入口。第一期范围为老师、学校及四级监管六端。

日期：2026-10-10。第一版、第二版均是第一期内的方案入口，不代表后续迭代或第二期。文档文件名中的 V2.0.0 是既有文档版本标识，不是建设期次。

## 一、当前交付边界

第一版是独立“关爱”一级菜单，第二版是在现有控辍保学预警记录中直接开展关爱。两者复用个案—多次关爱记录及内容表单；不采用已放弃的 V2.1 融合验证稿，不替换尚未确认的类型／方式建议枚举。

老师负责授权填写；学校查看并按原权限删除独立菜单整案；部、省、市、区县监管只读下钻；不包含家长端；其原型、专属文档及入口全部删除。当前是前端原型，不是已上线生产系统。

## 二、两版共用字段和交互

- 个案表单／摘要／详情及对应台账中，三类字段同时存在时固定为：**关爱来源 → 关联信息 → 关爱类型 → 关爱原因**。两类关联字段并存时，均位于来源之后、类型之前；其他原字段顺序不变。
- 单次内容顺序：关爱时间 → 执行人员 → 关爱方式 → 关爱结果 → 证明材料 → 继续跟进 → 下次跟进日期。
- 关爱时间默认今日；执行人员默认所选学生的全部班主任，仍按原权限和选择规则执行。
- 下次跟进日期非必填。继续跟进选“需要”时出现，可留空保存；提示仅为“请选择日期”。选“不需要”时隐藏并清空。只读对应字段有值回显，无值为“--”；不为此增加新的列表列。
- 来源／类型多选回显沿用第一版；关联信息无数据为“--”，有数据为“关联N条信息”；选择表单回显“已选N条关联信息”。
- 关联弹窗按类别分组、按选择顺序逐条完整换行，标题含总数，内容容器可滚动且隐藏滚动条。控辍“10个工作日内缺勤N个工作日”列出实际缺勤日期。手机使用底部弹窗，Web 使用居中弹窗和紧凑关闭按钮。
- 选择弹窗取消／确定统一底部同一行；取消不保存临时值。保留足量演示数据用于检验容器滚动。手机页面和弹窗留在手机容器内。
- 原有创建人／填报人、学年、最新记录编辑删除和简单状态规则保留；不扩展多人、多次记录的复杂状态变化场景。

## 三、第一版独立菜单

老师可新增个案并填写零至多条内容；无内容时为待关爱；同生同校未完结重复建案限制仍生效。产生首条内容后个案信息锁定。学校与监管台账一案一行，显示个案关爱总次数；详情倒序展示有效内容。具体权限与状态判定以端侧 PRD 为准。

## 四、第二版控辍保学入口

1. 无关爱内容：点“关爱”先确认个案信息，顺序为锁定来源“控辍保学” → 关联控辍保学 → 关爱类型 → 关爱原因，点下一步复用第一版内容表单。校验失败不进入下一步，不生成空个案。
2. 当前预警自动关联且不可取消；其他同生、同学年且符合原可选范围的预警仅作参考，已完结个案对应预警不可选。提示固定为：“当前预警自动关联。其他预警可作为历史参考；每个预警记录的关爱内容都单独保存”。
3. 每个入口预警对应自己的个案。参考预警不合案、不迁移或复制关爱内容，不改变原个案、材料、创建日期和版本，不计入当前次数。第一版同生未完结限制不阻断不同控辍预警分别建案。
4. 首条成功提交才创建当前个案及首条内容，创建日期取首次提交业务日期。已有当前空案则更新原空案；已有记录则点“继续关爱”直接进入内容表单，不再重复第一步。提交后个案信息锁定。
5. 预警详情保留劝返信息／关爱情况两个 Tab，独立计数。关爱情况标题右侧为状态，去掉旧底部状态操作卡。老师、学校及监管统一按有效个案是否存在显示个案信息卡：未建案不显示，已建案即使零次内容也显示；标题下、所有关爱内容之前始终只有一张，随页面正常滚动，不悬浮遮挡。
6. 学校及四级监管预警列表原“关联关爱”改为“关爱次数”：仅计算当前入口预警个案的有效关爱内容，有值“N次”，无内容“--”；点击次数进入当前预警关爱 Tab。不得计算参考预警次数或以个案数替代内容条数；已删除内容、被替代的审计旧版本均不计次，也不重复展示为一次关爱。
7. 详情个案摘要顺序：创建日期 → 关爱来源 → **关联信息** → 关爱类型 → 关爱原因。关联信息点击复用第一版只读分类弹窗；不影响劝返 Tab 和原预警详情字段。
8. 学校去掉旧“查看关爱”操作，其他操作竖向对齐；监管只保留居中详情按钮。监管按名称逐层下钻：部级省份→地市→区县→学校→明细，其他级从其权限起点进入，复用关爱菜单样式。
9. 控辍学生明细筛选维度为学年、年级、班级、学生姓名；其他原筛选、汇总统计字段、劝返流程及处理权限保留。预警时间不改成个案创建日期。

## 五、代码核对与验收

此次直接整理现有渲染函数，不追加后置插列：移除老师详情二次渲染补丁、Web 旧列表插列和筛选修补链，由现行学校台账／监管层级模块负责列表字段和筛选。保留正在使用的基础预警、劝返、权限和通用能力；历史及弃用原型不混入当前入口和发布包。

回归包括：六端脚本语法、启动、唯一 ID、相对资源；老师第一／二版表单与摘要顺序、日期选填、个案锁定与参考隔离；学校及四级监管新表头、实际次数、无内容空值、关联弹窗、详情顺序、双 Tab、筛选重置、层级下钻、第一版台账和详情；两种入口直达链接、旧审计版本不重复计次、监管跨入口次数一致、交付入口与当前文档相对链接。对应老师流程、Web流程、交付链接三组 .test.cjs，并提供 package.json 中的 npm test（依赖 jsdom 22.1.0）。

限制：这些是本地 DOM 回归，不等于真实浏览器视觉／触摸／上传验收。各 HTML 使用独立示例数据，刷新恢复样例，没有老师到学校、监管的真实跨端同步。
