> 产品版本：V2.0.0  
> 文档版本：V2.0.0_260929  
> 文档日期：2026-09-29  
> 适用范围：学校端Web／关爱管理  
> 状态：本期执行版；取代V1.0.0中“逐条关爱记录即个案”的旧口径。

## 需求背景

老师端改为先创建个案、再添加零至多次关爱。学校管理者需要按学生和个案查看本学年的总体情况、检查每次关爱过程，并在已有权限允许时删除整个个案；不在学校端代老师填写、编辑或继续跟进。学校列表、个案状态与老师端使用同一服务端数据和计算口径。

## 文档说明

### 名词解释

| 术语 | 定义 |
|---|---|
| 个案 | 同校同生在一段连续关爱中的容器，老师建案后立即产生，允许零次关爱。 |
| 关爱记录 | 该个案下的一次实际关爱；不单独作为学校列表的一行。 |
| 待关爱 | 个案当前有效关爱记录数=0。 |
| 关爱中 | 有记录，最新一条“继续跟进”=需要。 |
| 已完结 | 有记录，最新一条“继续跟进”=不需要。 |
| 创建日期／最近关爱日期 | 前者为建案时间的业务日期、始终固定；后者来自最新有效关爱记录，零记录时显示“--”。 |
| 关爱类型／来源／原因 | 个案层字段。类型与来源可多选；原因是一段≤100字事实描述；单次关爱不重复编辑这三项。 |

## 功能详细说明

### 业务范围与数据口径

| 项 | 规则 | 核验点 |
|---|---|---|
| 数据范围 | 当前学校、本学年、当前角色有权查看的个案；未删除有效个案每案只计一次。 | 创建日期用于学年归属，关爱记录日期变化不改变个案归属。 |
| 年级／班级／学生 | 来自当前学校所有学年、年级、班级和学生主数据；筛选级联。 | 历史个案展示创建时年级班级快照，查询可按系统既有学年规则检索。 |
| 次数 | 未删除有效关爱记录数，可以为0。 | 添加、删除、编辑记录后同步刷新。 |
| 状态 | 0→待关爱；最新记录“需要”→关爱中；最新记录“不需要”→已完结。 | 老师删除最新记录后重新计算；学校端不可手动改状态。 |
| 重复个案 | 同一学校同一学生可保留多件已完结旧案；同一时间最多一件待关爱／关爱中案。 | 不把后发生的已完结案合并进旧案。 |
| 排序 | 默认按个案创建日期倒序；详情各次记录按关爱时间倒序，同日按提交时间倒序。 | 条数与筛选结果统计同口径。 |

### 页面一：关爱管理／个案列表

#### 页面目标

让学校从个案维度查阅学生关爱执行情况和最新进展，保留学校端已有筛选区与表格风格，不引入录入入口。

#### 筛选与布局

| 区域 | 内容 | 交互 |
|---|---|---|
| 学生筛选 | 学年、年级、班级、学生姓名 | 顺序固定在其他筛选前；选学年后限制有效年级与班级；选择变化不立即查询，点“查询”执行。 |
| 其他筛选 | 关爱来源、个案创建日期范围、个案状态 | 来源支持多选个案的包含关系；日期格式YYYY-MM-DD。 |
| 查询操作 | 查询、重置 | 固定筛选区域首行右侧；左侧筛选项无论换几行都不得进入操作区边界。重置恢复默认条件并刷新。 |
| 留白 | 筛选与列表之间保留稳定纵向间距 | 不能紧贴表格；窄屏时列表内部水平滚动。 |

筛选项之间横向间隔40px；每个字段名与对应控件构成不可拆分的一组，特别是“学生姓名”与输入框必须始终同行。空间不足时按整组换行，不得只将输入框挤到下一行。
原“日期范围”筛选字段名改为“创建日期”，起止日期均按个案创建日期判断；不得按任一次关爱日期过滤，避免同一个案随继续跟进而错误出现或消失。页面右上角功能菜单入口统一显示为小绿点，点击后仍打开原功能菜单，保留可访问名称。

#### 台账字段与交互

| 顺序 | 字段 | 展示规则 |
|---|---|---|
| 1—3 | 学生姓名、年级、班级 | 学生／学籍信息；按可见权限展示。 |
| 4 | 创建日期 | 个案创建日期，YYYY-MM-DD，不使用首条关爱日期代替。 |
| 5 | 关爱类型 | 一个或多个类型标签；枚举与老师端完全一致。 |
| 6 | 关爱来源 | 一个或多个来源标签；枚举与老师端完全一致。 |
| 7 | 关联信息 | 无关联显示“--”；有关联显示“关联N条信息”，点击打开只读弹窗逐条查看。N按有效关联记录计，不按来源个数计。 |
| 8 | 关爱原因 | 一段最多100字的个案原因；列表超过10字省略，悬停展示全文。 |
| 9 | 关爱次数 | “N次”，含0次；点击可打开该个案详情。 |
| 10 | 最近关爱日期 | 最新有效记录日期；零记录“--”。 |
| 11 | 关爱结果 | 最新有效关爱结果；超过10字省略，悬停展示全文；零记录“--”。 |
| 12 | 个案状态 | 待关爱／关爱中／已完结，不再用“待跟进”代指整个个案。 |
| 13 | 操作 | 固定在表格右侧，仅“个案详情”和“删除个案”两项；操作区与滚动区边界平整。 |

列表顶部显示“本学年共 N 个关爱个案”，数量按可见个案计。筛选无结果时显示统一空态，不保留旧表格行。操作按钮的显示遵从已有职务管理菜单与权限开关；若业务选择“按钮可见但无权限”，点击统一提示“暂无权限”，服务端同样阻断。

### 页面二：关爱个案详情

| 区块 | 字段与顺序 | 行为 |
|---|---|---|
| 个案信息 | 学生姓名、学校、年级、班级、创建日期、关爱类型、关爱来源、关联信息、关爱原因、个案状态 | 来源和类型完整展示多项，原因换行显示全文；关联信息按“N条信息”打开弹窗，不提供编辑。 |
| 关爱情况 | 标题“关爱情况（共N次）”；最新一次在最上方 | N=0显示“尚无关爱记录”；不制造空白历史卡。 |
| 每次关爱卡 | 第N次／关爱时间、执行人员、关爱方式、关爱结果、证明材料、继续跟进、条件性下次跟进日期 | 与老师端字段名称和顺序一致；无任何编辑、继续跟进或删除记录按钮。 |
| 图片原图 | 缩略图点击后，原图浮层位于详情弹窗之上 | 关闭叉号距图片边缘约35px；关闭原图返回原详情，不关闭详情。 |
| 关闭 | 页脚“关闭”或右上叉号 | 返回原筛选和滚动位置。 |

每次关爱显示该条最新有效版本；历史编辑版本只进入审计查询。关爱方式按老师端当前枚举解释，不把旧原型的方式词擅自替换为不同业务含义。证明图片最多展示实际有效九张。

关联信息弹窗须遵循Web弹窗样式：标题显示总数，按控辍保学／心理测评等类别分组，类别内按关联选择顺序逐条完整换行；内容高度限制后可上下滚动但不显示滚动条。关闭按钮为Web小号次要按钮，不使用小程序通栏主按钮。控辍保学“10个工作日内缺勤N个工作日”须列出具体缺勤日期，不仅展示区间。四级监管端同口径、同交互。

### 弹窗：删除个案

标题“删除个案”；正文“确认删除该学生的个案吗？删除后不可恢复！”；按钮“取消／确定”。仅具备已有删除个案权限的学校角色可发起。点击确定后服务端重新校验权限、学年及个案未被他人删除；成功后列表和数量刷新、详情关闭；失败时显示明确提示，不得静默隐藏数据。删除审计由服务端留存，前台不提供恢复按钮。

## 通用权限、数据与异常规则

1. 权限由已有“职务管理”的菜单名称开关和“看见关爱菜单、查看详情、删除记录”三项权限开关确定；新原型不设计额外角色权限配置。
2. 学校端的新增关爱、编辑关爱、继续跟进及单次记录删除入口本期统一隐藏；直接调用旧入口也须服务端阻断。
3. 学校看到的个案类型、来源、原因、状态和关爱次数与老师端共用同一数据定义。预警／测评原记录状态变化不应在详情中静默改写已保存的关联快照。
4. 学生状态、权限或个案状态在页面停留期间变化，提交删除／打开详情时必须重新确认；权限不足提示“暂无权限”，对象已删除提示重新查询。
5. 图片及心理测评等敏感信息须沿用现有访问控制和审计策略，不能因为前台缩略图可见而开放原图直接访问。

## 验收要点

1. 老师端只建案不建首条关爱时，学校列表出现1件“待关爱／0次”个案。
2. 同案新增两次关爱仍只占1行、次数为2；详情以第2次在上、第1次在下。
3. 多选类型、来源和单段原因在列表／详情均正确；关爱记录不重复展示这些个案字段。
4. 删除老师端最新记录后，学校端次数、最近关爱日期和个案状态按剩余记录刷新。
5. 学校端每行仅“个案详情／删除个案”；详情各次关爱均无删除、编辑或继续跟进入口。
6. 筛选右侧固定、筛选与表格留白、列表横向滚动和最右侧固定操作列均正常。
7. 图片原图高于详情弹层，关闭叉号靠近图片且能回到原详情。
8. 越权删除、重复提交与已删除个案均由服务端阻断并反馈；家长端不在本期范围。
