## 3. 文档说明

### 3.1 名词解释

| 术语 / 缩略词 | 说明 |
|---|---|
| 【业务日期】 | 【使用学校/服务端哪个日期、时区、切日时点；与设备本地日期不一致时取谁。】 |
| 【业务对象 / 记录最小单位】 | 【一次操作产生几条记录；多对象、多项目时如何拆分、去重和计数。】 |
| 【有效记录】 | 【生成、撤销、软删与参与统计的条件；查询成功但记录数为零与请求失败须区分。】 |
| 【历史快照】 | 【成功时固化的字段、配置与人员/组织名称；后续变化是否追溯。】 |
| 【其他必须定义的术语】 | 【例如“本周”“当前学年”“净得分”“匿名”“待生效”，逐一给出判定口径。】 |

**填写口径：**

1. 功能章节按“业务模块/页面 → 查询条件 → 列表或看板字段 → 新建/编辑/详情 → 操作流程及结果 → 弹窗/子页面”连续排列；一个页面的内容留在该页面及其子章节内。若某页面没有某类内容，删除该小节，不保留空壳。
2. **一个可见字段、按钮或指标占表格一行**；在该行的规则单元格内用 `<br>` 分行写完来源、默认值、格式、权限、交互、联动、校验、逐字提示、成功与失败状态，不把同一字段拆成几行，也不以“同上/同理/按常规”代替规则。表格列数随内容采用参考文档的形态：查询条件四列，列表与看板三列，新建/编辑五列，单一概念或状态机两列。
3. **提示与校验就在触发它的字段、按钮、弹窗或页面节点处**。每条写明触发条件、前后端判定时点、提示的准确文案、展示位置/方式、值是否保留、按钮和弹窗是否继续可用。不要另建“提示文案汇总”“校验规则汇总”章节。组合字段的规则写在所涉操作节点，并点明关联字段；各单字段校验仍留在其字段行。
4. 数据来源要区分实时配置、提交快照、服务端聚合、客户端暂存与演示数据；写明读取、缓存、变更生效及并发校验时点。原型演示值不得充当正式接口或制度规则。字段格式要写清空值、0、`--`、换行起点、显示行数、截断、查看全文、单位、正负号与时间格式。
5. 所有数量、分值、金额、字数、图片数/大小、日期跨度、列表容量等数值，要在**对应字段行**写最小值、最大值、是否包含端点、精度、默认值、步长、手输格式、舍入方式、接近两端极值时的最后一步、达到极值的按钮外观及再次点击的提示；前端和服务端保持一致。限制若来自配置，写清权威配置入口、当前取值及更新后的处理，不能凭模板示例给业务字段定值。
6. 每个看板指标在**自己的字段行**分别写无数据、部分数据、全量数据时的展示和计算；页面或弹窗也必须写无数据时的文案、空态位置、按钮状态及仍可执行的操作。请求失败、数据未加载完成、业务上确实无记录是不同状态，不得混为“0”。
7. 每一组筛选都写明是否级联、上游和下游、有效旧选项如何保留、失效旧选项如何重置、组合条件按交集还是并集、取消/清空/重置后的结果，以及列表、看板、计数、排序和滚动位置如何同步。非级联也要明确写“否”。
8. 黄色仅表示用户明确“暂定”；红色仅表示用户明确要自行描述；其他未知写【待确认：问题】。颜色不支持时，方括号文字仍可辨识。定稿前逐项收敛，不得将未确认事项写为确定逻辑。
