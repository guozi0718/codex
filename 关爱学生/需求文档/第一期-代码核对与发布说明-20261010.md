# 第一期代码核对与发布说明

日期：2026-10-10。第一版与第二版均属第一期。本说明记录当前发布，不改变既定需求期次；已弃用 V2.1 不发布。

## 核查发现及修改方式

| 发现 | 修改方式 |
| --- | --- |
| 来源／关联／类型顺序不一致 | 直接调整第一版老师表单、详情、单次内容摘要及学校／监管台账、详情；第二版首次确认与摘要同序。不插入后置换列补丁。 |
| 日期提示混入“选填” | 提示统一“请选择日期”，非必填仍由字段规则和校验实现；继续跟进选需要、日期留空可提交。 |
| Web 预警表头和单位旧文案 | 改为“关爱次数”，按当前预警有效关爱内容计算 N次，无内容 --；参考预警不计入。 |
| 学校示例保留已替代历史版本，存在重复计次风险 | 第一版台账、详情及第二版预警计数排除 superseded 历史版本与已删除记录，保留审计数据而不当作新一次关爱；增加旧版本不增次回归。 |
| 监管个案聚合在初始化时缓存，不能包含后续预警演示追加的内容 | 渲染前从有效内容重新聚合，保持台账、汇总和预警详情次数一致；保留导出 API 数组引用并增加跨入口计数一致性回归。 |
| 发布包文档仍引用本地交付目录名 | 发布时将原型／需求路径适配仓库目录结构，增加交付链接测试，检查统一入口及当前正式文档的相对链接。 |
| Web 预警详情缺少关联信息 | 来源之后补齐条数按钮，复用第一版分类弹窗；现有记录证据缺失时回退当前预警及明确保存的参考 ID，不生成假关爱内容或合案。 |
| 老师详情重复渲染／事件包裹 | 将关联信息及学年、创建人、填报人校验整合到原渲染函数，移除重复渲染包装，保留已有保护。 |
| 共用脚本存在旧插列与筛选修补链 | 删除已由学校台账与监管层级模块替代的整段旧列表装饰和旧筛选重写；共用模块仅保留实际的详情与证据能力。 |
| 两种方案入口链接容易落入默认菜单 | Web 提供 #care-v1／#care-v2 明确入口，复用现有菜单方法；老师使用既有 #sc-care-menu／#sc-list。提供 index.html 集中入口。 |
| 文档仍有旧顺序／旧计数 | 原正式 PRD 原位更新，并增加第一期方案总览；不另起第二期需求，也不替换未经确认的枚举。 |

## 复验范围

- 七端加载、内嵌脚本解析、脚本和资源引用、唯一 ID。
- 老师第一／二版字段顺序、只读摘要、关联弹窗、日期提示与选填、首次成功建案、继续关爱跳过第一步、参考预警不合并、不迁移、次数隔离。
- 学校和四级监管的关爱次数实际计算、空值、详情关联信息和分类弹窗、双 Tab、原筛选与查询重置、名称下钻及返回；第一版台账和详情字段顺序。
- 第一／二版直达入口及交付目录相对链接。
- 工作稿、交付稿、发布包分别复验；发布只使用当前七端及配套模块和文档，不带临时依赖、历史原型、原始照片、弃用验证稿或本地 Git。

执行命令（原型目录）：安装依赖后 npm test，或分别 node 控辍保学-关爱联动.test.cjs、node 控辍预警-Web联动.test.cjs。依赖 jsdom 22.1.0 固定于 package.json。

上述为代码与 DOM 回归，不等于真实浏览器视觉、触摸和真实上传验收；未声称整个旧系统所有外围业务均已人工验证。当前原型无跨端后端持久化。正在使用的预警处理、劝返与权限代码保留；未盲删原始存档。
