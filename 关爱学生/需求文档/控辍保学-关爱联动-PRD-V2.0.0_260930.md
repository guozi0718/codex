# 控辍保学与关爱个案联动（第二版方案）

> 第一期确认补充（2026-10-10）：学校与四级监管台账的关爱来源、关爱类型列居中，按字符计数超过10字展示前10字加“...”，悬停显示完整文字。第二版老师及Web关爱情况在已建案后显示唯一顶部个案信息卡（创建日期→来源→关联信息→类型→原因）；未建案不显示，已建案零次也显示，增加内容不重复生成，不改变原内容顺序。家长端原型、专属文档、测试与入口删除，不保留旧副本或兼容入口。第一期范围为老师、学校及四级监管六端。

> 第一期定稿同步（2026-10-10）：第一版独立关爱菜单与第二版控辍保学入口均属第一期，不代表后续迭代或新增期次。关爱来源、关联信息、关爱类型同时出现时严格按此顺序；下次跟进日期仍非必填，提示仅为“请选择日期”。第二版学校及四级监管预警列表显示“关爱次数”（N次／--），详情来源后补齐关联信息及第一版分类弹窗。枚举暂不替换为未确认的建议字典。

> 产品版本：V2.0.0；第一期确认日期：2026-10-10。
> 适用范围：老师端控辍保学预警记录、学校端和部／省／地市／区县监管端的关联查看。  
> 第一版与第二版均属于第一期；三字段同时存在时按“关爱来源→关联信息→关爱类型”排列，其余校验、权限及归案限制保持不变。

## 1. 目标与边界

从控辍保学预警记录直接开展关爱，复用第一版“个案—多次关爱”实体和单次关爱表单。首次成功保存时才创建个案与首条关爱；劝返记录、预警处理状态和关爱个案状态独立维护，不能相互覆盖或合并计数。

当前归案规则修订为**每条预警独立对应一个关爱个案，不合并预警或关爱记录**。入口预警自动关联且不可取消；勾选其他预警只保存历史参考线索，不创建、合并、替换其个案，不迁移其关爱记录，也不把其次数计入当前预警。无关爱内容的预警不预先批量建案，首次成功保存关爱时才建立对应个案。控辍保学入口允许同一学生的不同预警分别建案，第一版独立关爱菜单仍保留同生未完结重复建案限制。

2026-10-08 的 V2.1 融合验证稿已于 2026-10-10 放弃，不作为本方案依据。本轮不采用其支持需求分类、措施多选、权限演示开关或显式结束流程；字段、默认值、既有简单状态规则仍沿用原第二版。多人、多次记录下的个案状态变化场景暂不扩展。

学校和监管端不代老师填写关爱。学校独立关爱菜单保留授权详情和删除整案；监管端只读。本期不包含家长端，其专属原型、文档与入口全部删除。

## 2. 老师端入口与状态

| 当前预警关联状态 | 按钮 | 点击后的页面 |
| --- | --- | --- |
| 无个案 | 关爱 | 先填写个案信息，下一步填写首次关爱内容。 |
| 已关联空个案，关爱次数为0 | 关爱 | 同样先确认个案信息；首次保存更新原空个案，不重复创建。 |
| 至少一次关爱，个案关爱中 | 继续关爱 | 沿用锁定的个案信息，直接填写新一次关爱，不重复第一步。 |
| 个案已完结 | 继续关爱（置灰） | 不允许新增；详情可查看历史。 |

“处理／重新处理”仍为独立劝返流程。详情不另设底部“个案状态／继续跟进／重新处理”卡片。

只保留第二版控辍关爱入口：不再打开旧 `sc-care-add` 页面；旧捕获阶段点击拦截脚本和旧表单已移除。控辍保学主页返回外部系统的链接目前暂时禁用，不是永久产品规则；恢复须确认目标地址有效后另行启用。

## 3. 第一步：个案信息

学生信息由入口预警带入，只读且不可换学生。字段严格按以下顺序：

| 顺序 | 字段 | 必填及交互 | 回显 |
| --- | --- | --- | --- |
| 1 | 关爱来源 | 固定为“控辍保学”，不可点击、无选择箭头。 | 仅显示“控辍保学”，与其他值同为12px；不附加“已锁定”字样。 |
| 2 | 关联控辍保学 | 当前预警自动选中且不可取消，满足必填；同生、同学年其他信息可选作历史参考。 | 初始显示“已选1条关联信息”；选中其他参考后显示“已选N条关联信息”，条数包含当前预警，不直接堆叠明细。 |
| 3 | 关爱类型 | 必填；第一版类型枚举，底部多选。 | 单行显示，多项用顿号连接，超长省略；保留统一箭头。 |
| 4 | 关爱原因 | 必填；最多100字，空白不通过。 | 多行文本框，沿用第一版样式和提示。 |

底部按钮为“下一步”。未通过校验不能进入第二步，不生成个案。第一版与第二版选择弹窗均将“取消／确定”放在底部同一行并列；取消不保存临时勾选，确认时按选择顺序保存。日期选择也先临时选择再确定。示例至少超过5条，选项容器显示约5行并可上下滚动，滚动条不展示。

控辍信息示例使用第一版格式：连续缺勤N个工作日（日期范围）；10个工作日内缺勤N个工作日（逐个列出具体缺勤工作日）。详细信息在弹窗内完整换行，不省略；只在字段回显处显示条数。

关联控辍保学标题下提示：“当前预警自动关联。其他预警可作为历史参考；每个预警记录的关爱内容都单独保存”。保留原有同生、同学年和数据源可选范围，本轮不扩展已完结记录或多人状态场景。关联证据与真实预警均需保留稳定 ID，不按文本匹配正式数据。当前预警的归案 ID 与其他预警的参考 ID 分开保存；第一版独立关爱菜单的关联信息仍为非必填，不改为必填。

不同预警的个案、关爱记录、材料、填报人、版本历史和创建日期保持独立。当前预警详情及次数只读取自己个案的记录；参考其他预警不迁移、复制或联合计算其记录。参考预警没有个案时也不自动创建。继续关爱只追加到当前预警原个案，按原倒序规则展示。劝返与预警处理状态不变；不会因为被其他预警选作参考而变化。

内部来源沿用第一版“辍学预警”枚举以兼容既有数据；第二版控辍页面显示“控辍保学”。

## 4. 第二步：关爱内容

学生及“关爱来源→关联信息→关爱类型→关爱原因”作为上方只读摘要；关联信息按条数回显并可点击查看；第一步选中的关联信息保存在草稿中并随首次关爱提交。第二步不能修改个案信息。返回或放弃不保存草稿、不产生空个案；再次开展首次关爱须重新确认。

字段顺序与第一版完全一致：

| 顺序 | 字段 | 要求 |
| --- | --- | --- |
| 1 | 关爱时间 | 必填，默认今日，不得晚于今日；沿用第一版日期选择。 |
| 2 | 执行人员 | 必填，默认该学生对应的全部班主任；支持多选和原回显规则。 |
| 3 | 关爱方式 | 必填，第一版枚举与底部选择弹窗。 |
| 4 | 关爱结果 | 必填，描述过程与结果，完整换行。 |
| 5 | 证明材料 | 非必填，最多9张，JPEG／JPG／PNG，单张不超过10M；沿用上传、预览和删除交互。 |
| 6 | 继续跟进 | 必填，选择需要／不需要；这是记录字段，不随入口按钮改名。 |
| 7 | 下次跟进日期 | 非必填；“需要”时展示，可留空提交，不做强制跟进安排；不需要时清空隐藏值。提示文字仅为“请选择日期”，不附加“选填”；卡片、列表、详情对应字段有值显示日期，无值显示“--”。 |

保存校验、提示点、创建人／填报人权限、记录编辑与删除规则沿用第一版。点击入口“继续关爱”不能绕过第一版权限或修改锁定的个案字段。

首次成功保存才同时产生当前预警个案和首条关爱。创建日期取首条关爱**成功创建／提交的业务日期**，不是预警日期，也不是回填的关爱时间，更不继承参考预警个案的日期。已有空个案时只更新当前预警的空个案，不重复创建；后续新增、编辑不改变创建日期。

## 5. 预警详情与学校／监管端列表

### 预警详情

基本信息下方保留“劝返信息／关爱情况”两个 tab。默认劝返；切换不丢失当前预警。

- 劝返信息：独立计数，逐次展示日期、方式、老师、结果及佐证材料；不显示个案状态。
- 个案卡显示条件只依赖是否存在有效个案，不依赖内容次数；已建案时在标题之后、所有内容之前固定显示一张。该卡随页面正常滚动，不是悬浮遮挡层，内容再多也不重复。老师、学校与监管统一；无个案不显示，已建案零次仍显示。来源后的关联信息仍可打开分类弹窗。
- 关爱情况：标题“关爱情况（共N次）”右侧显示个案状态；个案信息按“创建日期→关爱来源→关联信息→关爱类型→关爱原因”展示。关联信息无数据为“--”，有数据为“关联N条信息”，点击复用第一版只读分类弹窗（总数、分组、完整换行、滚动内容区及Web小号关闭按钮）。记录倒序展示，字段使用第一版顺序。
- 零记录分别展示空态，长内容完整换行。
- 详情底部不追加状态与处理操作块；操作留在预警列表。
- 学校／监管 Web 弹窗保留紧凑关闭按钮，不使用小程序整行大按钮。

### Web 预警列表

保留原预警字段和顺序，不替换成关爱菜单的统计字段。关爱次数列有记录显示“N次”，无记录显示“--”；点击计数查看当前预警的关爱 tab。计数代表当前预警的有效关爱记录数，不是个案数；参考预警、已删除记录、被替代的历史版本不计次，不重复展示。

学校操作列去掉“查看关爱”，保留原详情及处理／重新处理操作，使用固定列宽对齐；监管详情按钮居中，监管端不提供填写和编辑。学校删除关联整案后，当前页预警关联计数立即重算，劝返记录仍保留。

## 6. 监管层级与设计一致性

| 端 | 控辍预警起点及下钻顺序 |
| --- | --- |
| 部级 | 省份 → 地市 → 区县 → 学校 → 预警明细 |
| 省级 | 地市 → 区县 → 学校 → 预警明细 |
| 地市 | 区县 → 学校 → 预警明细 |
| 区县 | 学校 → 预警明细 |

点击名称本身下钻，与第一版关爱菜单一致，不增加“操作／查看”列。返回恢复上一层和日期筛选。演示树包含省属／市直分支，按既定树显示。

汇总保留“预警记录数、待处理数、已处理数”和合计，只让第一列名称随层级变化。根据2026-10-08最新批注，学校与各监管端控辍预警学生明细的学生维度筛选统一按**学年、年级、班级、学生姓名**排列；学校控辍劝返台账同样配置四项。其他条件保留：预警明细保留处理状态、预警类型、预警时间；劝返台账保留劝返方式、日期范围。预警时间不得改为创建日期，统计汇总层级不强行加入学生级筛选。明细表原字段及顺序不变。

四项默认全部学年、全部年级、全部班级、空姓名，查询按组合条件匹配。学年按记录业务日期所在学年计算（9月起至次年8月，如2026年5月属于2025学年）；年级保留原年级及入学级显示。切换学年清空年级／班级并刷新可选项，切换年级清空班级；姓名支持包含匹配。查询与日期、处理状态／类型／方式共同生效；重置清空四项，并沿用各菜单既有日期默认口径。暂用演示记录生成下拉枚举，正式后端应使用学年与班级等稳定标识。

各端复用关爱菜单的标题、筛选间距40px、圆角、边框、表格、名称按钮、绿色 Web 操作、返回交互和无感滚动样式。学生姓名标签与输入框同行。移动端选择统一底部弹窗、约5行可滚动容器和第一版回显规则。

本轮不以清理代码为由改变劝返原有字段和处理权限。预警与劝返演示本学年日期为2026年9月，上一学年保留历史标识；真实产品不能改写历史事件日期。

## 7. 数据、权限与实现边界

1. 正式实现以学校 ID、学生 ID、学年、入口预警 ID、个案 ID 关联，不用姓名推断；入口预警建立唯一性约束。
2. 当前入口预警与个案一一对应，`warningIds` 仅保存当前入口预警 ID；其他预警保存于 `referenceWarningIds`，仅作参考线索，不作为归案或计数条件。关联证据、个案多次关爱、预警多次劝返分别保存。
3. 原子化首次建案，失败不产生空个案；重复提交由后端唯一性与幂等校验防止重复。
4. 来源、类型、原因提交后锁定；删除、编辑与身份／学年范围由服务端校验，不能只靠按钮置灰。
5. 当前 HTML 是独立演示实例，新增、删除只作用于当前页面；刷新恢复样例，老师填写不自动同步到学校或监管。生产跨端同步、真实上传和审计落库仍需后端实现。
6. 本地文件不支持存储时使用会话内回退，不能因为读取偏好失败而中断菜单初始化。
7. 当前交付版使用本地脚本、已编译样式和本地图标；不依赖远程运行时 Tailwind 编译或图标 CDN。历史原型仅存档，不作为当前入口。
8. 未随本交付包提供的管理端审核、旧外部演示及账号跨端跳转已停用；不显示假的操作成功结果。
