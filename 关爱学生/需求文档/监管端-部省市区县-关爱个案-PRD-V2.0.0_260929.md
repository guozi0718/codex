> 适用范围：部、省、地市、区县四级监管Web端  
> 状态：本期执行版；取代V1.0.0中的逐次关爱列表与两态口径。

## 需求背景

关爱业务以“学生个案”为管理对象，个案可以先建档、后实施关爱，并持续追加多次记录。监管端应按既有行政层级权限逐级查看学校个案和每次关爱情况，保持只读，不替学校或老师修改学生关爱内容。四级监管在同一字段定义、状态定义与详情顺序上完全一致，仅数据范围和上级导航层级不同。

## 文档说明

### 名词解释

| 术语 | 说明 |
|---|---|
| 监管层级 | 部→省→地市→区县→学校；用户仅查看已有组织授权覆盖的下级范围。 |
| 关爱个案 | 同一学校同一学生的一段连续关爱过程；可先有个案而无关爱记录。 |
| 关爱记录 | 老师一次成功提交的实际关爱；一个个案可有零至多条。 |
| 关爱状态 | 0条=待关爱；最新有效记录选“需要”=关爱中；选“不需要”=已完结。 |
| 关爱类型／来源／原因 | 个案层信息：类型和来源可多选，原因只有一段≤100字文本。 |
| 最近关爱 | 个案最新有效关爱记录；没有记录时日期、结果显示“--”。 |
| 本学年 | 使用已有学年配置，筛选与统计口径须同学校端一致。 |

## 功能详细说明

### 业务范围与数据口径

| 指标／规则 | 定义 | 核对方式 |
|---|---|---|
| 个案数 | 当前行政范围内、当前学年、未删除且有权查看的个案数；0记录案也计1。 | 下级学校去重汇总；同一学生多个已完结个案分别计数。 |
| 关爱次数 | 个案未删除的有效关爱记录数。 | 学校台账与监管详情一致。 |
| 待关爱数 | 有个案但0条有效记录。 | 不误记为关爱中。 |
| 关爱中数 | ≥1条，最新有效记录“继续跟进”=需要。 | 旧版“待跟进”不再作为整案状态名称。 |
| 已完结数 | ≥1条，最新有效记录“继续跟进”=不需要。 | 删除最新记录后可回关爱中或待关爱。 |
| 数据范围 | 组织授权可见学校、本学年个案；学校内学生与班级来自已有主数据。 | 后端基于组织树和当前角色校验，不以页面路径判权。 |
| 时间与排序 | 个案创建日期和每次关爱时间统一YYYY-MM-DD；台账默认按创建日期倒序，详情按关爱时间倒序。 | 同日以服务端提交时间稳定排序。 |

### 页面一：四级汇总与下钻

#### 页面目标

部级看授权省域、省级看授权地市、地市看授权区县、区县看授权学校；每级逐层到学校个案台账。汇总卡片与下级数量用个案口径，状态分类沿用待关爱／关爱中／已完结。

#### 展示和交互

| 层级 | 直接下钻目标 | 数据约束 |
|---|---|---|
| 部级 | 省级单位 | 仅已授权省域；不得通过手改参数跨省查看。 |
| 省级 | 地市 | 仅本省有权地市。 |
| 地市 | 区县 | 仅本市有权区县。 |
| 区县 | 学校 | 仅本区县有权学校。 |

部级首层展示省份；省级首层展示地市（首行可包含“省属”）；地市首层展示区县（首行可包含“市直”）；区县首层展示学校。每次点击名称只进入下一层，最终点击学校进入该校多个个案的台账。首层标题统一为“关爱个案汇总”；下钻后展示返回按钮及“关爱个案汇总-当前省／市／区县／学校名称”，逐级返回，不跨层跳转。省属、市直为实际组织归属节点，不混算到普通地市或区县。示例原型中北京、河北、陕西及其下级组织仅是演示数据，不能作为真实行政统计。

汇总表统一为“关爱学生数、关爱个案数、待关爱、关爱中、已完结、各关爱类型个案数”。个案数按个案ID去重，关爱学生数按学校与学生ID去重；每个个案在一个状态列且仅一个状态列计数。多选关爱类型的个案可在多个类型列各计1，因此类型列横向求和允许大于个案总数，不作为校验总数。筛选条件作用于汇总行、合计行和学校个案台账同一数据集；层级下钻、返回保留或明确重置条件，不能出现“汇总数按关爱记录、学校台账按个案”的混用。学校被转隶、权限变更时重新查询并服务端重鉴权。

### 页面二：学校关爱个案台账

#### 筛选与布局

部、省、市、区县四级及下钻到学校个案台账后的筛选区完全一致，仅保留三组：创建日期（起止两个日期框）、关爱类型（全部及家庭变故、学业困难、同伴关系、行为问题、经济困难、特殊家庭、其他）、个案状态（全部、待关爱、关爱中、已完结）。不再显示“日期方式”；起止日期相同即可筛选单天。日期只按个案创建日期匹配；多选类型按“包含所选类型”匹配。筛选组之间横向间隔40px，组内字段名与输入控件必须同行、不拆散。查询和重置始终固定于筛选区首行右侧；空间不足时筛选组整体滚动，不使标签与控件断行。筛选与列表之间保留间距。窄屏横向滚动只发生在表格容器，最右“操作”列固定，边界视觉连续。

#### 台账字段

| 顺序 | 字段 | 规则 |
|---|---|---|
| 1—3 | 学生姓名、年级、班级 | 只展示授权学校范围内学生；历史快照不因当前升年级而静默改写。 |
| 4 | 创建日期 | 个案创建日期，与首条关爱时间区分；无记录案仍有值。 |
| 5 | 关爱类型 | 多选标签；家庭变故、学业困难、同伴关系、行为问题、经济困难、特殊家庭、其他。 |
| 6 | 关爱来源 | 多选标签；辍学预警、心理测评、班主任发现、任课教师反映、学生主动反映、家长反映、困难学生、欺凌事件、其他。 |
| 7 | 关联信息 | 没有关联显示“--”；有关联显示“关联N条信息”，点击打开只读弹窗。N按关联记录计数。 |
| 8 | 关爱原因 | 一段事实文本，≤100字；超10字省略，悬停全文。 |
| 9 | 关爱次数 | N次，允许0次；点击进入同一案详情。 |
| 10 | 最近关爱日期 | 最新有效记录日期；0次“--”。 |
| 11 | 关爱结果 | 最新有效结果；超10字省略，悬停全文；0次“--”。 |
| 12 | 个案状态 | 待关爱／关爱中／已完结。 |
| 13 | 操作 | 固定右侧，仅“个案详情”。无删除、编辑、继续跟进按钮。 |

筛选及列表不得暴露其他学校数据；无法匹配时展示“暂无符合条件的关爱个案”，不展示旧数据残留。关爱类型筛选匹配多选类型中的任一对应值，具体组合查询语义需由后台与前台保持一致。

### 页面三：关爱个案详情

#### 页面目标

监管人员只读复核“学生为何建案”和“实施了哪些关爱”。详情在学校台账之上弹出，关闭后保留原筛选与滚动位置。

#### 内容顺序

| 区块 | 字段与展示 | 交互 |
|---|---|---|
| 个案信息 | 学生姓名、学校、年级、班级、创建日期、关爱类型、关爱来源、关联信息、关爱原因、个案状态 | 多选项和原因完整换行；关联信息按条数打开只读弹窗。 |
| 关爱情况 | “关爱情况（共N次）”；最新一次在最上方 | 0次显示空态；不生成虚构的首次记录。 |
| 单次关爱卡 | 第N次、关爱时间、执行人员、关爱方式、关爱结果、证明材料、继续跟进、条件性下次跟进日期 | 字段名、顺序与老师端一致，历史记录无按钮。 |
| 图片原图 | 最多九张证明材料按学校端样式排成三列缩略图；点击任意缩略图在当前详情之上弹出原图 | 可逐张查看；关闭叉号靠近图片边缘约35px；关闭后仍停留在详情。 |
| 关闭 | 顶部叉号／页脚关闭 | 返回原台账，不改变筛选值。 |

关爱方式采用老师端统一枚举：谈心谈话、家校沟通、家访、学习辅导、生活关怀、同伴关系协调、行为教育、资助帮扶、返校关怀、其他。监管端不擅自根据旧原型值推断真实历史值；历史值如不在新枚举中，后端应保留原始展示并在迁移方案中处理。证明材料只展示有访问权限的有效图片。详情显示当前有效内容，不默认向监管普通详情公开每版审计快照。

关联信息弹窗与学校端同口径：标题含总数，按类别分组，类别内按关联选择顺序逐条完整换行；内容可上下滚动但不显示滚动条。Web关闭按钮采用小号次要按钮。控辍保学“10个工作日内缺勤N个工作日”列明具体缺勤日期。四级监管的列表和详情均使用此展示，不因下钻层级改变。

## 通用权限、数据与异常规则

1. 四级监管端始终只读。菜单可见性、详情可见性沿用现有职务管理和组织授权；未经授权点击旧入口提示“暂无权限”，服务端拒绝越权访问。
2. 学校端或老师端增删改关爱后，监管汇总、台账、详情从同一有效数据集刷新；不存在监管侧独立维护的副本口径。
3. 对已删除个案或发生权限变化的详情请求，明确提示重新查询或暂无权限，不以旧弹窗缓存继续展示。
4. 预警／心理测评及证明图片涉及未成年人敏感信息；原始关联记录链接、缩略图和原图均应经过与详情相同的授权校验，访问审计保留。
5. 本期不在监管端提供新增个案、关爱、继续跟进、编辑或删除功能，也不设计监管代校操作。

## 验收要点

1. 部、省、地市、区县均可在有权范围逐级到学校，越权路径无法取得任何个案详情。
2. 同案2次关爱在台账只占1行、次数为2；零记录个案仍占1行且状态待关爱。
3. 四级监管列表和学校端的个案状态、次数、最近关爱、最新结果及类型／来源／原因一致。
4. 详情的多次关爱最新在上，字段顺序与老师端一致；无修改、删除或继续跟进入口。
5. 老师删除最新关爱后，监管状态按剩余最新记录重算；删除唯一关爱后回待关爱。
6. 筛选首行右侧固定查询／重置，表格操作列固定，图片原图位于详情之上并可正确关闭。
7. 本期不出现家长端入口或监管代填功能。
